# 📘 LVM (Logical Volume Manager) — COMPLETE NOTES

---

## 1️⃣ Why LVM exists (problem → solution)

### ❌ Without LVM (traditional partitions)

- Disk → fixed partitions
- Example:

  ```
  /var 10G (FULL ❌)
  /home 20G (FREE but useless)
  ```

- Resizing requires:
  - unmount
  - repartition
  - data movement
  - downtime

---

### ✅ With LVM

- Disks are combined into a **storage pool**
- You slice storage **when needed**
- Resize **live**, no reboot

👉 **LVM = flexibility + scalability**

---

## 2️⃣ LVM architecture (MUST MEMORIZE)

```
Disk / Partition
     ↓
Physical Volume (PV)
     ↓
Volume Group (VG)
     ↓
Logical Volume (LV)
     ↓
Filesystem
     ↓
Mount point
```

### Mapping to old world:

- LV ≈ smart partition
- VG ≈ big free space pool

---

## 3️⃣ LVM components explained (simple)

### 🔹 Physical Volume (PV)

- A disk or partition given to LVM
- Example:

  ```bash
  /dev/xvdf
  /dev/xvdz
  ```

Command:

```bash
pvcreate /dev/xvdf
```

---

### 🔹 Volume Group (VG)

- Pool of storage made from one or more PVs

Example:

```bash
vgcreate vg_data /dev/xvdf /dev/xvdz
```

---

### 🔹 Logical Volume (LV)

- Virtual partition created from VG
- This is what we format and mount

Example:

```bash
lvcreate -L 10G -n lv_data vg_data
```

---

## 4️⃣ Filesystem rules (VERY IMPORTANT)

✔ Filesystem is created **ONLY on LV**
❌ Never on VG
❌ Never on PV

```bash
mkfs.ext4 /dev/vg_data/lv_data
```

---

## 5️⃣ Viewing LVM status (daily commands)

```bash
pvs   # Physical volumes
vgs   # Volume groups
lvs   # Logical volumes
```

Very important for debugging.

---

## 6️⃣ FULL PRACTICAL – Create LVM (from scratch)

### Step 1: Create PVs

```bash
pvcreate /dev/xvdf /dev/xvdz
```

### Step 2: Create VG

```bash
vgcreate vg_data /dev/xvdf /dev/xvdz
```

### Step 3: Create LV

```bash
lvcreate -L 20G -n lv_data vg_data
```

### Step 4: Create filesystem

```bash
mkfs.ext4 /dev/vg_data/lv_data
```

### Step 5: Mount

```bash
mkdir /data
mount /dev/vg_data/lv_data /data
```

---

## 7️⃣ Extending (resizing) LVM (MOST IMPORTANT FEATURE)

### 🔹 Extend LV (ext4)

```bash
lvextend -L +10G /dev/vg_data/lv_data
resize2fs /dev/vg_data/lv_data
```

✔ No unmount
✔ No reboot

### 🔹 Extend using ALL free space

```bash
lvextend -l +100%FREE /dev/vg_data/lv_data
resize2fs /dev/vg_data/lv_data
```

---

## 8️⃣ Shrinking LVM (⚠️ DANGEROUS – THEORY LEVEL)

⚠️ Only **ext4**, never XFS.

### Steps (must follow order):

```bash
umount /data
e2fsck -f /dev/vg_data/lv_data
resize2fs /dev/vg_data/lv_data 15G
lvreduce -L 15G /dev/vg_data/lv_data
mount /data
```

🚨 Wrong order = DATA LOSS

👉 In production, shrinking is avoided.

---

## 9️⃣ Deleting LVM (clean removal)

### Step 1: Unmount

```bash
umount /data
```

### Step 2: Remove LV

```bash
lvremove /dev/vg_data/lv_data
```

### Step 3: Remove VG

```bash
vgremove vg_data
```

### Step 4: Remove PV

```bash
pvremove /dev/xvdf /dev/xvdz
```

---

## 🔟 Adding a new disk later (real world)

Attach new disk `/dev/xvdy`

```bash
pvcreate /dev/xvdy
vgextend vg_data /dev/xvdy
```

Now VG size grows — existing LVs can be extended.

## 1️⃣1️⃣ LVM snapshots (basic idea)

- Used for backup
- Copy-on-write
- Not full copy

Example:

```bash
lvcreate -s -L 2G -n snap_data /dev/vg_data/lv_data
```

## 1️⃣2️⃣ LVM vs RAID (interview)

| LVM           | RAID                    |
| ------------- | ----------------------- |
| Flexibility   | Redundancy              |
| Resize easily | Disk failure protection |
| Logical layer | Physical redundancy     |

👉 Often **used together**

---

## 1️⃣3️⃣ Common mistakes (AVOID)

❌ Formatting PV or VG
❌ Shrinking XFS
❌ Using `/dev/sdX` instead of LV path
❌ Forgetting `resize2fs` after extend
❌ Using LVM on root disk while learning

---

## 1️⃣4️⃣ Interview one-liners (MEMORIZE)

- **What is LVM?**

  > LVM provides flexible disk management by abstracting physical storage into logical volumes.

- **Where is filesystem created?**

  > On logical volumes only.

- **Why use LVM?**

  > To resize and extend storage without repartitioning or downtime.
